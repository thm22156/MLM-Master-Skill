# 50-02_更新维护计划

## 一、更新触发机制

### 1.1 定期检查周期
每季度检查一次所有源Skill的更新状态。
检查范围：系列五（马列毛理论）、系列三（无趣的人）、系列一（赵皓阳）、系列二（嬴月咏）、系列四（千户学）。

### 1.2 触发式更新条件
以下情况触发紧急更新（不等季度周期）：

- 系列五（马列毛理论Skill）有任何更新——这是最高优先级，因为它直接影响整合体系的理论核心
- 任何源Skill出现重大理论立场转变
- 任何源Skill新增了对其核心框架有重大影响的内容

### 1.3 "重大"的量化辅助标准

**以下情况视为"重大"（触发更新）：**
- 源Skill的核心公理/根本法则有增删改（即使只改一条，只要涉及核心）
- 源Skill新增内容超过原有内容的20%
- 源Skill对马列毛主义经典作家的引用方式发生明显变化

**以下情况不视为"重大"（可延至定期检查）：**
- 仅增加案例（总数增加但核心框架不变）
- 修正错误（纠错性质而非新增内容）
- 调整表述（不涉及实质立场变化）

**灰色地带（"可能是重大的"）：**
- 新增内容在10%-20%之间且涉及理论分析而非纯案例
- 删除或弱化了此前明确支持的某个理论观点
→ 灰色地带由审查者裁定，存疑时按"重大"处理（宁可多审不可漏审）

---

## 二、更新决策流程

### 2.1 评估阶段
对源Skill的更新内容进行初步评估：

- 更新的规模（新增/修改/删除的比例）
- 更新的性质（补充案例/修正错误/调整框架/改变立场）
- 对整合体系的潜在影响（无影响/局部调整/结构性调整）

### 2.2 决策标准
触发整合体系更新的条件：

- **系列五更新**：必须响应——即使只是补充一个案例或修正一处错误，也必须在修正日志中记录
- **系列三更新**：评估后决定——新增视频是否涉及核心公理的改变？如果仅增加案例，记录但不必立刻更新；如果公理有变化，触发更新
- **系列一/二更新**：审查后决定——新增内容是否可以通过批判过滤纳入？如果方向一致且经过马列毛审查后可用，则更新30_工具层
- **系列四更新**：严格审查——大部分新增内容可能不可纳入，只有在极少数情况下才触发更新

### 2.3 决策僵局的处理

当审查者无法达成一致时：

**步骤1：充分讨论**
- 每位审查者说明自己的判断和原著依据
- 不得以"我感觉""我认为"替代原著依据
- 如果某审查者无法提供原著依据，其意见降权

**步骤2：表决**
- 充分讨论后仍无法达成一致，按少数服从多数原则表决
- 如果票数相等（如2:2），延后决策——该更新暂缓纳入，标记为"待定"，同时在50-04修正日志和50-09已知开放问题清单中记录分歧内容

**步骤3：复审**
- 延后期间收集更多依据并定期复审
- 每季度复审一次待定项
- 复审时如有新原著依据，重新讨论

**绝对禁止：**
- 以"权威"替代原著依据（"某某同志说了……"不能替代原著原文）
- 在分歧未解决时强行纳入——"存疑不纳入"优先于"勉强纳入"

## 三、更新执行流程

### 3.1 10_理论方法统一体的更新（来自系列五更新）
1. 对比新旧版本，提取差异
2. 审查差异内容是否符合马列毛原著（再次审查——因为源Skill更新可能是自动化的，可能有新引入的错误）
3. 确定受影响的具体子文件
4. 修改受影响的文件
5. 更新跨板块连接（如果修改影响了其他板块的连接关系）
6. 更新修正日志（记录：更新日期、来源、差异内容、修改位置）
7. 如果需要，更新快速入口/速查卡

### 3.2 30_批判过滤工具的更新（来自系列一/二/四更新）
1. 对新增内容进行马列毛审查（使用与初始改造相同的审查标准）
2. 如果可用，执行术语替换+理论锚定
3. 标注置信度（新增内容的置信度初始为L或M）
4. 更新改造操作手册（50-03）中的相应记录
5. 在30的README中标注本次更新的来源和日期

## 四、新增Skill的纳入机制

### 4.1 纳入资格审查
新增UP主提炼形成的Skill必须通过以下审查才能进入整合体系：

- **初步方向审查**：该Skill的根本方向是否符合马列毛主义？（参考对系列一至四的审查方法论——判断其属于四个定性中的哪一档）
- 如果初步审查判定为"大体符合但存在偏差"或更高 → 进入下一步
- 如果初步审查判定为"违反或背叛"→ 拒绝纳入，记录拒绝原因

### 4.2 纳入后的处理
按照审查结论确定处理方式：

- **"严格符合"** → 可考虑纳入理论-方法统一体或方法论训练层
- **"大体符合，显著偏差"** → 纳入批判过滤工具层，执行改造
- **"大体符合，偏差最重"**（如千户学）→ 仅提取极少量的技术性内容，其余全部排除

纳入时必须执行与初始整合相同的改造标准。

## 五、版本管理

### 5.1 版本编号规则
**主版本号.次版本号.修订号**

- **主版本号**：宪法准则有修改 或 板块结构有重大调整
- **次版本号**：子模块有新增或删除 或 源Skill更新触发了内容修改
- **修订号**：修正错误、更新案例、完善表述等小幅修改

### 5.2 版本发布
每次发布新版本时，必须附带：

- 更新内容摘要
- 受影响的文件清单
- 如果涉及理论内容的修改，附马列毛原著依据

## 六、内容衰减与淘汰机制

### 6.1 时政案例的时效性管理
每个时政案例标注"适用时间区间"。每年度审查时，超过5年的时政案例评估是否移入"历史案例"或删除。

### 6.2 批判过滤工具的再审查
30_批判过滤工具层的内容，每两年重新审查一次：

- 上游源Skill是否有重大更新导致当前内容过时？
- 改造后的工具在使用中是否暴露了未被发现的问题？
- 是否有新的马列毛原著文献需要重新锚定？

### 6.3 淘汰标准
以下内容应当淘汰：

- 时政案例超过适用时间区间且无历史分析价值
- 批判过滤工具已被上游源Skill的新版本完全覆盖或否定
- 任何被发现与马列毛原著存在不可调和冲突的内容

淘汰时必须在修正日志和删除内容记录中记载：淘汰内容、淘汰原因、马列毛原著依据。

### 6.4 紧急下架机制

**触发条件（任一）：**
- 被证实含有与马列毛原著存在原则性冲突的内容，且此前改造中未被识别
- 经群众路线验证发现其分析结论系统性地偏离马列毛主义立场
- 收到多个独立来源的、有原著依据的质疑

**流程：**
1. 收到触发信号——立即评估严重性（紧急/常规）
2. 紧急情况——立即将该文件从"可用"状态标记为"暂停使用"
   - 在文件开头增加醒目警告：⚠️ 本文件因[原因]被暂停使用，待复审
   - 在30层README中更新状态
3. 复审——按修改的双重审查流程进行审查
4. 结果——
   - 如果确认有问题：修改或删除，记录在修正日志和删除记录中
   - 如果确认无问题：撤销"暂停使用"标记，恢复为"可用"状态
   - 如果无法确认（存疑）：维持"暂停使用"标记，标注"置信度待定"
5. 通报——在修正日志中公开发布，不隐瞒

**紧急下架不需要等待年度审查或两年再审查周期。宁可错停（可恢复），不可错放（不可逆）。**

## 七、不可变性保护

### 7.1 受保护的核心内容
以下内容在任何更新中均不得修改（除非有马列毛原著中的新发现直接推翻当前理解——在人类现有认知范围内，这种可能性极低）：

- 宪法正文6条（绝对不可变）
- 宪法附则中的原理性阐述（不可变，除非有原著新发现）
- 10_理论方法统一体中标注[明言]的命题（不可变）
- 暴力革命与巴黎公社原则的明确立场（绝对不可变）

### 7.2 修改的审查防火墙
任何触及以下内容的修改，必须经过双重审查：

- 涉及宪法附则的修改
- 涉及10_理论方法统一体中标注[蕴含]的命题
- 涉及批判过滤标准（30层）的修改

**双重审查 =** 第一重（马列毛原著一致性审查）+ 第二重（审查上一次同类修改至今的累积效应，确保小步修改没有累积成方向性偏移）

### 7.3 更新频率的上限
为防止"更新疲劳"导致审查质量下降——整合体系的实质性更新（次版本号及以上）每年不超过4次。紧急修复（修订号级别——如修正错别字、修正引文错误）不受此限。

### 7.4 受保护内容的例外处理流程

极罕见情况——马列毛原著文献新发现直接重大修正当前理解：

1. **确认**——新发现是否确实来自原著文献本身？（非"新解释"——而是原著文献新发现、新翻译或此前被忽视的重要段落）
2. **论证**——撰写双重论证报告（新发现 vs 当前依据、双方原著）
3. **双重审查**——至少两位熟悉原著的同志独立审查
4. **通过后**——修正日志详细记录全过程、保留旧版、发布时附带摘要

**暴力革命原则在任何条件下不适用此例外——推翻它的"原著新发现"不存在。**

### 7.5 回滚机制

**触发条件（任一）：**
- 更新后发现宪法正文或附则被错误修改
- [明言]标记被错误删除或曲解
- 更新引入了与原著的不可调和冲突
- 灌输入口更新后经群众路线检验确认"比旧版更差"

**流程：**
1. 确认——确认问题的严重性和影响范围
2. 回滚——恢复受影响文件至上一版本（从50-04获取旧版本号）
3. 记录——50-04中记录回滚原因、涉及文件、新旧版本号
4. 吸取教训——将原因写入50-09已知开放问题清单以预防再次发生

版本号格式：主.次.修订 + 回滚后缀 "-rollback-YYYYMMDD"
回滚不算新主次版本。

## 八、多人协作编辑规范

### 文件所有权
每个板块指定一位主要维护者负责内容质量审查。主要维护者有权接受或拒绝其他人提交的修改。

### 编辑冲突解决
当多人对同一文件提交了不同的修改时：
1. 优先采用有原著依据的修改
2. 如果双方都有原著依据——由主要维护者裁定。如无法裁定——进入决策僵局处理机制（见2.3）
3. 如果双方都没有原著依据——两位提交者先补原著依据再提交

### 修改权限分级
- **L1：所有人**——修正错别字、格式调整
- **L2：板块维护者**——修改本板块的子文件（新增/修改/删除）
- **L3：宪法维护者（至少2人）**——修改宪法正文、附则、导言
- **L4：仅体系总维护者**——修改宪法级约束、不可变性保护内容

### 提交信息规范
每次提交附带以下信息：
- 修改范围（哪些文件）
- 修改性质（新增/修改/删除/回滚）
- 原著依据（涉及理论内容时必须）
- 关联的问题编号（如关联50-09中的某个问题）
